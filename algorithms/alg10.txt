🐾 Модуль 10: Фундаментальные свойства алгоритмов — критерии валидации инструкций 🛠️
Алгоритм — это не просто последовательность действий, а строго определённая математическая и логическая система правил. Чтобы произвольная инструкция официально считалась алгоритмом, она должна обладать шестью фундаментальными свойствами.
📦 🛠️ 🧠 🎯 🤖 🧩 ⚡ 📦 🛠️ 🧠 🎯 🤖 🧩 ⚡
1️⃣ 🌍 Массовость (Massiveness / Generality)
Алгоритм создается не для одного конкретного числа или случая, а для решения целого класса однотипных задач.
💡 Суть: Универсальность алгоритма. Меняются входные данные (аргументы), но сам порядок действий остаётся неизменным и успешно приводит к цели.
📌 Пример: Алгоритм поиска корней квадратного уравнения через дискриминант (D=b
2
 −4ac) работает для любых действительных коэффициентов a,b,c, а не только для какого-то одного уравнения.
❌ НЕ алгоритм: Инструкция: «Чтобы сложить 2 и 3, возьмите 2, прибавьте 3, получите 5». Она не обладает массовостью, так как неприменима для сложения других чисел.
🔍 Тестовые маркеры: «Класс задач», «универсальность», «различные наборы входных данных», «общность».
📦 🛠️ 🧠 🎯 🤖 🧩 ⚡ 📦 🛠️ 🧠 🎯 🤖 🧩 ⚡
2️⃣ 🧩 Дискретность (Discreteness)
Процесс решения задачи расчленен на отдельные, изолированные друг от друга элементарные шаги (команды).
💡 Суть: Исполнитель не может выполнять всё одновременно или непрерывно. Только завершив шаг №1, он имеет право перейти к шагу №2.
📌 Пример: Пошаговая инструкция сборки мебели: «1. Распакуйте каркас. 2. Закрутите четыре угловых болта. 3. Установите крышку».
❌ НЕ алгоритм: Фраза «Постройте дом» или «Отремонтируйте ноутбук». Это сложные непрерывные процессы без явного разделения на атомарные шаги.
🔍 Тестовые маркеры: «Пошаговость», «отдельные этапы», «последовательность изолированных команд».
📦 🛠️ 🧠 🎯 🤖 🧩 ⚡ 📦 🛠️ 🧠 🎯 🤖 🧩 ⚡
3️⃣ 🎯 Детерминированность / Определённость (Determinism / Definiteness)
Каждый шаг алгоритма должен быть абсолютно четким, точным и трактоваться единственно возможным способом.
💡 Суть: В алгоритме нет места двусмысленности, случайному выбору (если это не стохастический алгоритм) или интуиции исполнителя. При одинаковых исходных данных разные исполнители (или один и тот же компьютер) всегда должны получать абсолютно идентичный результат.
📌 Пример: Команда компилятора x = x + 1 детерминирована.
❌ НЕ алгоритм: Кулинарный рецепт с формулировками: «Добавьте немного сахара по вкусу», «Варите до готовности», «Перемешайте несколько раз». Компьютер не знает, сколько это — «по вкусу».
🔍 Тестовые маркеры: «Однозначность», «определённость», «неизменность результата при одинаковых входах», «отсутствие двусмысленности».
📦 🛠️ 🧠 🎯 🤖 🧩 ⚡ 📦 🛠️ 🧠 🎯 🤖 🧩 ⚡
4️⃣ 🏁 Конечность / Финитность (Finiteness)
Работа алгоритма обязательно должна завершиться за конечное (пусть даже очень большое) число шагов.
💡 Суть: Алгоритм не имеет права уходить в бесконечный цикл без критерия выхода. Понятие бесконечного алгоритма в классической теории — это нонсенс.
📌 Пример: Цикл for i in range(100) гарантированно завершится.
❌ НЕ алгоритм: Инструкция «Пока горит свет, выполняйте чтение», если свет в комнате горит вечно и нет условий для его выключения.
🔍 Тестовые маркеры: «Завершаемость», «конечное число шагов», «остановка процесса».
📦 🛠️ 🧠 🎯 🤖 🧩 ⚡ 📦 🛠️ 🧠 🎯 🤖 🧩 ⚡
5️⃣ 📥 Результативность (Effectiveness)
Это свойство идет рука об руку с конечностью, но имеет важный логический нюанс, который часто выносят в отдельные тестовые вопросы.
💡 Суть: По завершении алгоритма исполнитель обязан получить конкретный результат (ответ на вопрос, измененный массив, файл) либо строгое сообщение о том, что задача решения не имеет. Алгоритм не может закончиться "ничем".
📌 Пример: Алгоритм деления чисел a/b при b=0 завершается и выдает ошибку: «Деление на ноль невозможно». Это валидный результат.
🔍 Тестовые маркеры: «Получение искомого результата», «выходные данные», «сигнал о невозможности решения».
📦 🛠️ 🧠 🎯 🤖 🧩 ⚡ 📦 🛠️ 🧠 🎯 🤖 🧩 ⚡
6️⃣ 🤖 Понятность (Understandability)
Алгоритм должен состоять только из тех команд, которые входят в СКИ — Систему Команд Исполнителя.
💡 Суть: Исполнитель (робот, человек, микроконтроллер) должен уметь физически и логически выполнить предложенное действие. Если команда лежит вне СКИ, алгоритм ломается.
📌 Пример: Для процессора понятны низкоуровневые команды вроде MOV, ADD, PUSH.
❌ НЕ алгоритм: Написать инструкцию для первоклассника, используя интегральные исчисления, или дать кофейному автомату команду «Свари борщ». Борща нет в его СКИ.
🔍 Тестовые маркеры: «СКИ (Система команд исполнителя)», «доступные исполнителю действия», «язык исполнителя».

🧠 Быстрая диагностика для тестов (Таблица триггеров)
Формулировка в вопросе	Свойство алгоритма
«Один и тот же алгоритм можно применять для разных исходных данных»	Массовость
«Алгоритм разделен на последовательность отдельных шагов»	Дискретность
«При одинаковых входных данных всегда получается один и тот же результат»	Детерминированность (Определённость)
«Процесс решения задачи прекращается за конечное число шагов»	Конечность
«Алгоритм обязательно должен приводить к определенному ответу/результату»	Результативность
«Все команды алгоритма должны входить в СКИ»	Понятность

🧩 Мини-итог для КТА
Инструкция становится алгоритмом только тогда, когда она понятна исполнителю, разбита на дискретные шаги, абсолютно однозначна (детерминирована), гарантированно завершается с конкретным результатом и способна решать целую массу похожих задач. Если выпадает хотя бы один пункт — перед нами просто текст или бесконечный цикл, но не алгоритм.
