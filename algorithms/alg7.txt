🐾 Модуль 7: Оценка сложности алгоритмов — Big-O нотация и рост времени 📈
В этом модуле разбираем, как измерять асимптотическую эффективность алгоритмов и предсказывать их поведение при лавинообразном росте входных данных n.
📦 📈 ⏱️ 🧮 🚀 🐢 🔥 📦 📈 ⏱️ 🧮 🚀 🐢 🔥
1️⃣ Что такое O-нотация и её законы для тестов 📈
Big-O показывает верхнюю границу (худший случай) того, как растёт потребление ресурсов алгоритма (время или память) при увеличении размера входных данных n→∞.
⚠️ 3 золотых правила раскрытия Big-O в тестах:
Константы не имеют значения: O(2n)→O(n), O(500)→O(1).
Оставляем только самую быстрорастущую часть (доминирующий член): Если получилось O(n
2
 +n+logn), ответом в тесте будет строго O(n
2
 ).
Правило произведения (вложенность): Если цикл на n шагов вложен в другой цикл на n шагов →O(n⋅n)=O(n
2
 ).
Правило суммы (последовательность): Если сначала идёт один цикл на n шагов, а после него (не внутри!) другой цикл на m шагов →O(n+m). Если они одинаковы →O(n+n)=O(2n)→O(n).
📦 📈 ⏱️ 🧮 🚀 🐢 🔥 📦 📈 ⏱️ 🧮 🚀 🐢 🔥
2️⃣ O(1) — Константная сложность ⚡
Время выполнения операции абсолютно неизменно и не зависит от размера структуры данных.
📌 Примеры:
Доступ к элементу массива по индексу (arr[i]).
Вставка и удаление в конец стека (push/pop) или очереди.
Хэш-таблицы: поиск, вставка и удаление в среднем случае.
Любые базовые математические формулы.
🧠 Маркер в коде: Нет циклов, зависящих от переменной n.
📦 📈 ⏱️ 🧮 🚀 🐢 🔥 📦 📈 ⏱️ 🧮 🚀 🐢 🔥
3️⃣ O(log n) — Логарифмическая сложность 🔍
Идеальная скорость. При увеличении количества данных в миллион раз, количество шагов алгоритма увеличится всего примерно в 20 раз.
💡 Суть: На каждом шаге алгоритма размер обрабатываемых данных уменьшается в два раза (делить пополам).
📌 Примеры:
Бинарный поиск (Binary Search) в отсортированном массиве.
Поиск, вставка и удаление в сбалансированных деревьях (AVL, Красно-чёрные).
🧠 Маркер в коде: Переменная цикла в каждой итерации умножается или делится на число:
Python
while n > 1:
    n = n // 2  # Или i = i * 2
📦 📈 ⏱️ 🧮 🚀 🐢 🔥 📦 📈 ⏱️ 🧮 🚀 🐢 🔥
4️⃣ O(n) — Линейная сложность 🐢
Время растёт строго пропорционально объёму данных. Данные увеличились в 10 раз — время выросло в 10 раз.
📌 Примеры:
Линейный поиск элемента в неотсортированном массиве.
Поиск минимума или максимума за один проход.
Обход связного списка.
🧠 Маркер в коде: Один цикл, который идёт от 0 до n с фиксированным шагом (i += 1).
📦 📈 ⏱️ 🧮 🚀 🐢 🔥 📦 📈 ⏱️ 🧮 🚀 🐢 🔥
5️⃣ O(n log n) — Квазилинейная сложность («Золотой стандарт») 🚀
Самая лучшая скорость, которую математически можно получить для универсальных сортировок сравнением.
💡 Суть: Массив делится логарифмически (logn уровней рекурсии), но на каждом уровне приходится просматривать все элементы линейно (n операций).
📌 Примеры:
Сортировка слиянием (Merge Sort).
Пирамидальная сортировка (Heap Sort).
Быстрая сортировка (Quick Sort) в среднем и лучшем случае.
🧠 Маркер в коде: Внешний цикл или рекурсия делит задачу пополам, а внутри выполняется линейный проход по элементам.
📦 📈 ⏱️ 🧮 🚀 🐢 🔥 📦 📈 ⏱️ 🧮 🚀 🐢 🔥
6️⃣ O(n²) — Квадратичная сложность 🐢🐢
Эффективность алгоритма начинает резко падать при больших n. При n=100 000 такой алгоритм уже намертво зависнет на реальном тесте.
📌 Примеры:
Простые сортировки: Пузырьковая (Bubble), Вставками (Insertion), Выбором (Selection).
Поиск дубликатов в неотсортированном массиве методом «каждый с каждым».
Худший случай для Quick Sort (когда Pivot выбран неудачно).
🧠 Маркер в коде: Вложенные циклы, где оба зависят от n:
Python
for i in range(n):
    for j in range(n):
        # операция
📦 📈 ⏱️ 🧮 🚀 🐢 🔥 📦 📈 ⏱️ 🧮 🚀 🐢 🔥
7️⃣ O(n³) — Кубическая сложность 🔥
📌 Примеры: Нативное (неоптимизированное) перемножение двух матриц размером n×n, или поиск комбинаций из трёх элементов полным перебором.
🧠 Маркер в коде: Три вложенных цикла for.
📦 📈 ⏱️ 🧮 🚀 🐢 🔥 📦 📈 ⏱️ 🧮 🚀 🐢 🔥
8️⃣ O(2ⁿ) — Экспоненциальная сложность 💥
Ужасная производительность. Добавление всего одного элемента на вход удваивает время работы алгоритма.
📌 Примеры:
Нахождение n-го числа Фибоначчи через наивную рекурсию без мемоизации.
Перебор всех возможных подмножеств множества из n элементов.
Задача о Ханойских башнях.
🧠 Маркер в коде: Рекурсивная функция, которая внутри себя делает два и более рекурсивных вызова.
📦 📈 ⏱️ 🧮 🚀 🐢 🔥 📦 📈 ⏱️ 🧮 🚀 🐢 🔥
9️⃣ O(n!) — Факториальная сложность 💀
Худший из возможных кошмаров разработчика. Алгоритм становится непригодным уже при n>12.
📌 Примеры:
Задача коммивояжёра (Traveling Salesman Problem) методом полного брутфорса (перебором всех городов).
Генерация абсолютно всех перестановок массива.

⚠️ Главные ловушки в тестовых вопросах (Разбор трюков)
🛑 Ловушка 1: Вложенный цикл с константой
Python
for i in range(n):
    for j in range(1000):  # Тут константа!
        print(i)
Ошибочный ответ: O(n
2
 ), потому что циклы вложены.
Правильный ответ: O(n). Внутренний цикл всегда делает ровно 1000 шагов, а константы мы отбрасываем (O(1000n)→O(n)).
🛑 Ловушка 2: Уменьшающийся внутренний цикл
Python
for i in range(n):
    for j in range(i, n):  # j начинается с i
        print(j)
Ошибочный ответ: Раз внутренний цикл уменьшается, это что-то вроде O(nlogn).

🛑 Ловушка 3: Строки в циклах (Особый капкан для Python/Java)
Конкатенация строк (s += char) в цикле выполняется за линейное время O(k), где k — текущая длина строки, так как строка копируется в памяти заново. Поэтому создание строки из n символов через += в цикле for суммарно займёт O(n
2
 ), а не O(n)!

🧩 Мини-итог
В тестах всегда ищи маркеры изменения переменных в циклах. Если шаг делится/умножается — ищи в ответах логарифм logn. Если циклы независимы — складывай их сложности, если вложены — перемножай, но предварительно убирай любые жестко прописанные числа-константы.
